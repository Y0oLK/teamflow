# TeamFlow — Domain & Technical Glossary

This glossary defines the domain terminology, architectural concepts, security principles, and engineering jargon utilized throughout the **TeamFlow** specifications and codebase.

---

## 1. Domain & Business Concepts

| Term | Definition in TeamFlow Context |
|---|---|
| **Organization (Tenant)** | A discrete corporate workspace representing a company, agency, or department. All projects, tasks, members, and files belong to an Organization. Organizations are strictly isolated from one another. |
| **Membership** | The formal association between a `User` and an `Organization`, defining the user's role within that workspace (e.g., `OWNER`, `ADMIN`, `MEMBER`, `GUEST`). |
| **Project** | A structured operational container within an organization grouping related tasks, milestones, and assigned project members. |
| **Project Member** | A specific organization member explicitly granted access to a project. Non-member employees cannot see private projects. |
| **Task** | The fundamental unit of work containing title, description, priority, status, assignees, due dates, subtasks, and dependencies. |
| **Kanban Board** | A visual agile workflow management tool grouping tasks into vertical status columns (`BACKLOG`, `TODO`, `IN_PROGRESS`, `IN_REVIEW`, `DONE`, `CANCELLED`). |
| **Subtask** | A checklist item nested within a parent task representing granular steps toward task completion. |
| **Task Dependency** | A directional relationship where Task A blocks Task B. Task B cannot be marked `DONE` until Task A is resolved. |
| **Activity Log / Audit Trail** | An immutable, chronological record of security and business events (e.g., role changes, project archival, task status transitions) capturing actor, action, and timestamp. |

## 2. Technical & Architectural Concepts

| Term | Definition in TeamFlow Context |
|---|---|
| **Modular Monolith** | A software architecture where all application logic resides in a single unified codebase and deployment container, but is rigorously partitioned into decoupled, self-contained domain modules with clear public interfaces. |
| **Multi-Tenancy** | An architectural model where a single instance of the application and database serves multiple customer organizations while logically isolating their data so that no tenant can access another's records. |
| **Tenant Isolation** | Security mechanisms (NestJS guards, Prisma query filters, and DB constraints) guaranteeing that every database query is scoped strictly to the authenticated user's active organization. |
| **Role-Based Access Control (RBAC)** | An authorization mechanism restricting system access based on assigned organizational and project roles. |
| **Fractional Indexing** | A technique for ordering cards on a Kanban board by assigning each item a floating-point number (e.g., between `1.0` and `2.0`, insert `1.5`), enabling $O(1)$ reordering without updating all surrounding records. |
| **Optimistic UI** | A frontend pattern where user actions (like dragging a Kanban card) immediately update the local user interface before the network request finishes, followed by automatic rollback if the server rejects the mutation. |
| **State Reconciliation** | The process by which a client compares its local cache against the server's authoritative state upon reconnection and resolves discrepancies. |
| **Directed Acyclic Graph (DAG)** | A graph with directed edges and no cycles. Used in TeamFlow to model task dependencies, ensuring that a task cannot directly or indirectly depend on itself. |
| **Redis Pub/Sub Adapter** | A distributed messaging layer that allows multiple Socket.IO server instances to broadcast real-time events to connected clients regardless of which server instance holds the client's socket connection. |
| **Pre-Signed URL** | A time-limited, cryptographically signed URL generated by the backend granting temporary direct upload or download permissions to S3/MinIO object storage without exposing private cloud credentials. |

## 3. Security & Cryptographic Terms

| Term | Definition in TeamFlow Context |
|---|---|
| **Argon2id** | The modern, memory-hard winner of the Password Hashing Competition (PHC). TeamFlow utilizes Argon2id with memory cost 64MB ($m=65536, t=3, p=4$) to resist GPU and ASIC brute-force attacks. |
| **HttpOnly Cookie** | A secure browser cookie flag that prevents client-side JavaScript from reading sensitive session tokens, providing robust immunity against token theft via Cross-Site Scripting (XSS). |
| **SameSite=Strict** | A cookie attribute instructing browsers never to send the cookie in cross-site requests, providing defense against Cross-Site Request Forgery (CSRF). |
| **BOLA / IDOR** | **Broken Object-Level Authorization** (also known as Insecure Direct Object References). A critical vulnerability where an application fails to verify whether the authenticated user possesses authorization to manipulate a requested object ID. |
| **Magic Bytes** | The initial binary sequence of a file used to identify its true MIME format independently of the file extension or client-supplied `Content-Type` header. |
| **Rate Limiting** | Restricting the number of incoming API requests per client IP or user account within a specific time window to mitigate brute-force and Denial-of-Service (DoS) attacks. |

## 4. Engineering & Delivery Standards

| Term | Definition in TeamFlow Context |
|---|---|
| **SRS** | **Software Requirements Specification.** A formal IEEE 830-compliant document detailing what a software system will do and how it will perform prior to implementation. |
| **Definition of Done (DoD)** | A formal agreement specifying the technical, quality, and documentation requirements that must be met before a milestone or feature can be accepted as complete. |
| **Acceptance Criteria** | A set of predetermined conditions that a software feature must satisfy to be accepted by the product owner, formatted as **Given-When-Then** scenarios. |
| **ADR** | **Architectural Decision Record.** A lightweight document capturing an important architectural decision, along with its context, considered options, trade-offs, and consequences. |
